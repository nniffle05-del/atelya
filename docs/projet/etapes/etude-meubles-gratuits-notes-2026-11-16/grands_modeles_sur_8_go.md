# Large open image-to-3D models (TRELLIS.2, SAM 3D Objects, TRELLIS v1, Pixal3D): commercial licence chain in the EU, and what really runs on an 8 GB RTX 2070 — state at 16 November 2026

Scope note. Reprioritised on 16 Nov 2026 by the coordinator: production will run on RENTED 24-48 GB GPUs (Linux possible); the 8 GB RTX 2070 (Windows 11, 16 GB RAM) only matters for development and first trials. "Free" = no per-object fee and no subscription. The deciding factor is the licence chain for commercial use in the EU. Sections 1 and 2 are therefore the core; sections 3 to 8 are kept short.

## 1. TRELLIS.2: is there a complete commercially-clean chain (weights, DINOv3, background removal or user mask, mesh extraction, texture baking, GLB export without nvdiffrast)?

### Takeaway
Yes, through ComfyUI's NATIVE nodes (in ComfyUI core since PR #14718, merged 22 Aug 2026): MIT weights, post-processing re-implemented in PyTorch/SciPy (I checked the source files: no nvdiffrast, nvdiffrec, xatlas, kaolin or pytorch3d import), BiRefNet (MIT) or a user mask for the background, GLB export by ComfyUI. The one piece that is neither permissive nor removable is the DINOv3 image encoder: Meta's "DINOv3 License" does not prohibit commercial use and names Meta Platforms Ireland as counterparty for EEA licensees, but Meta may change it with immediate effect and the official download is manually gated. Microsoft's own code is NOT clean as shipped: its GLB export imports nvdiffrast ("for research or evaluation purposes only and not for any direct or indirect monetary gain") and its default background remover RMBG-2.0 is CC BY-NC.

### Inferences
- Clean TRELLIS.2 production chain: ComfyUI (GPL-3.0, run as a separate tool/server on the rented GPU, driven through its API, exactly like Blender) + TRELLIS.2 weights (MIT) + DINOv3 ViT-L (DINOv3 License) + BiRefNet (MIT) or the product's own mask (the workflow has a switch to skip background removal) + ComfyUI's PyTorch/SciPy remesh, decimate, UV unwrap and bake + GLB save. Nothing in that chain is non-commercial, AGPL or EU-excluding.
- GPL-3.0 has no network-use clause; running ComfyUI as an internal service and shipping only the generated GLB does not convey ComfyUI. This is the usual reading, to be confirmed by counsel; I only read the licence header.
- DINOv3 is the residual legal risk: (a) unilateral modification clause "effective immediately", (b) termination on breach with deletion, (c) California forum, (d) the company should request access from Meta's official gated repository in its own name rather than rely on the ungated Comfy-Org copy, whose "mit" tag cannot relicense Meta's weights. The company would not redistribute DINOv3 (only GLBs leave the machine), so the redistribution clause is not triggered.
- Microsoft's statement that nvdiffrast is "used only for visualization" is contradicted by its own export module, which imports nvdiffrast for baking; a commercial user must not use `o_voxel.postprocess.to_glb` as shipped.
- The project page's "solely for academic and research purposes ... not intended for commercial exploitation" is about the page's demonstration materials, while the code and the weights are each explicitly MIT; still worth showing to counsel because Microsoft never answered the commercial-use question.
- The default ComfyUI template downloads and loads Pixal3D by default. Under the project's rule against EU-excluding terms (`extra_gated_eu_disallowed: true` on the original repository), the workflow should be edited so that only the TRELLIS.2 diffusion model and `dino_v3_vit_l.safetensors` are downloaded and loaded.
- "No non-commercial dependencies" rests on the vendor's statement plus my import check of 13 files; it is not a full legal audit of ComfyUI (transitive Python packages were not reviewed).

### Gaps
- No Microsoft statement on commercial use of generated assets; no answer on training-data licences.
- I did not find a copy of the DINOv3 agreement inside the Comfy-Org repository (not checked file by file).
- Licence of the NAF upsampler weights packed in `dino_v3_L_naf_fp32.safetensors` and of the MoGe weights (both only needed for Pixal3D).
- No measured time per object for the native nodes on a 24-48 GB GPU.

## 2. SAM 3D Objects: decisive clauses of the SAM License, gating conditions, licences of mandatory dependencies

### Takeaway
The SAM License (last updated 19 Nov 2025) does not prohibit commercial use, contains no restriction on outputs and does not exclude the EU (Meta Platforms Ireland is the counterparty for EEA licensees). It is a custom Meta licence: redistribution only under the same agreement, ITAR/military/weapons prohibitions, termination on breach with deletion, indemnity, California law, and Meta may modify it with immediate effect. Weights are manually gated (first name, last name, date of birth, country, affiliation, job title). Mandatory dependencies are BSD/Apache/MIT plus GPL tools; the two traps are the texture bake (the code default says "nvdiffrast", the official demo overrides it to "pytorch3d") and stray non-commercial packages in the install list (`smplx`; Kaolin 0.17.0's `non_commercial` folder, which SAM 3D does not import in the file I read).

## 3. TRELLIS.2 on 8 GB for trials (ComfyUI native, int8 / GGUF weights)

### Takeaway
Unproven. There is no official VRAM or RAM figure for the native nodes and I found no first-hand 8 GB report. ## 6. Generic tricks: Windows "CUDA - Sysmem Fallback", stage offload, sparse-backend swaps

### Takeaway
Stage-by-stage model offload is the trick that works (large VRAM cuts at little time cost). Windows shared-memory fallback only prevents the crash and can cost one to two orders of magnitude in time. No verified report shows a 24-32 GB image-to-3D model running usefully on 8 GB this way.

### Cited Findings
- VERIFIED-PAGE. NVIDIA support article "System Memory Fallback for Stable Diffusion" (updated 31 Oct 2023): driver 536.40 lets an application "use shared memory in cases that exhausted the GPU memory", running "at lower speeds"; from driver 546.01 the NVIDIA Control Panel setting "CUDA - Sysmem Fallback Policy" can be set per program to "Prefer No Sysmem Fallback", with "the risk of a crash" when memory runs out; "Driver Default" re-enables the fallback. — [nvidia.custhelp.com a_id/5490](https://nvidia.custhelp.com/app/answers/detail/a_id/5490)
- VERIFIED-PAGE. Offload results: SAM 3D Objects to about 14.6 GB peak at ~37 s per object — [Apptainer_SAM3D](https://github.com/DMackRus/Apptainer_SAM3D); TRELLIS v1 to 6-8 GB on an RTX 2070 SUPER — [TRELLIS issue #31](https://github.com/microsoft/TRELLIS/issues/31); TRELLIS.2 official code with default `low_vram`: 3.2-5.8 GB PyTorch peak on a 16 GB card — [maksonlee.com](https://www.maksonlee.com/install-trellis-2-wsl-2-ubuntu-26-04-rtx-5060-ti-16gb/)
- VERIFIED-PAGE. Shared-memory spill with the native ComfyUI 3D nodes: 3.5-7.8 GB shared on a 12 GB card; one image still finished "in under 2 minutes", another crashed — [ComfyUI issue #15996](https://github.com/Comfy-Org/ComfyUI/issues/15996). Cost when memory is short: about one hour per SAM 3D object on 12-16 GB cards versus ~35 s on 24 GB — [sam-3d-objects issue #19](https://github.com/facebookresearch/sam-3d-objects/issues/19); 23 minutes for TRELLIS v1 on 4 GB — [TRELLIS issue #31](https://github.com/microsoft/TRELLIS/issues/31)
- VERIFIED-PAGE. A memory-saving sparse backend can silently ruin quality: TRELLIS.2 with `SPARSE_CONV_BACKEND=spconv`, 2.67 GiB instead of 14.09 GiB but 12,500 connected components instead of 64. — [TRELLIS.2 issue #23](https://github.com/microsoft/TRELLIS.2/issues/23)
- UNVERIFIED. A too-big model "runs 10-30x slow rather than crashing" with the fallback — [runaihome.com](https://runaihome.com/blog/shared-gpu-memory-slow-local-ai-sysmem-fallback-fix-2026/)

### Inferences
- On a 16 GB RAM PC, shared GPU memory is limited to roughly half of system RAM and competes with staged weights, so the fallback is weaker than in the cited reports (32-64 GB RAM).

### Gaps
- No report of tiled/sparse-chunked decoding bringing TRELLIS.2 or SAM 3D down to 8 GB.

## 7. Other open image-to-3D models (late 2025-2026) with official 8-12 GB support

### Takeaway
Not researched in depth after the reprioritisation. At search level, no late-2026 open model combines top quality, official 8-12 GB support, a PBR textured mesh and a permissive licence; the small-VRAM names that come up are older or weaker, or output Gaussian splats.

### Cited Findings
- UNVERIFIED (search summaries; official pages not opened). Idol (Speridlabs, late Oct 2026): single image → Gaussian splat, Apache 2.0, "peaks at 7.2 GB of VRAM" — [explainx.ai](https://explainx.ai/blog/speridlabs-idol-image-to-3d-gaussian-splat-open-model-2026); TripoSR (MIT, about 6 GB), Stable Fast 3D (about 6 GB; licence reported inconsistently), TripoSG 1.5B (MIT, 8 GB minimum, geometry only) — [builderai.tools](https://builderai.tools/blog/single-image-to-3d-model-pipeline-2026), [cmarix.com](https://www.cmarix.com/blog/top-open-source-ai-models-for-3d-image-generation/)
- VERIFIED-PAGE. Open requests to add newer models to ComfyUI core: "Request for Hi3D support" (#17321, 23 Oct 2026), "Request for UltraTex support" (#17261, 21 Oct 2026). — [ComfyUI issue search](https://github.com/Comfy-Org/ComfyUI/issues?q=is%3Aissue+trellis2+OR+pixal3d+OR+%22trellis.2%22)
- VERIFIED-PAGE. Pixal3D card: Low-VRAM mode "reduces peak VRAM by loading models on-demand" (1536 standard, 1024 low-VRAM), no VRAM figure — [TencentARC/Pixal3D](https://huggingface.co/TencentARC/Pixal3D). UNVERIFIED: third-party node packs quote "at least 16 GB", "24 GB or more recommended", "3-5 min" per mesh — [dreamrec/ComfyUI-Pixal3D](https://github.com/dreamrec/ComfyUI-Pixal3D)

### Inferences
- For "the same piece of furniture as in the photo" as a PBR mesh, TRELLIS.2 remains the open reference that is licence-clean in the EU; with rented 24-48 GB GPUs there is no need for a "mini" model in production.

### Gaps
- Licence, VRAM and quality of Hi3D, UltraTex, Idol, TripoSG, Direct3D-S2, Step1X-3D not verified on official pages.

## 8. Output type, partly hidden objects, single vs multiple images

### Takeaway
TRELLIS.2 (and Pixal3D) give a textured mesh with full PBR maps but expect one clean, unoccluded object image. SAM 3D Objects is the only one built for partly hidden objects in real photos (photo + mask) but its mesh texture is the weakest. TRELLIS v1 accepts several images through an untrained trick.

### Cited Findings
- VERIFIED-PAGE / VERIFIED-RAW. TRELLIS.2 via ComfyUI: GLB with base color, roughness, metallic, baked normal and ambient-occlusion maps; decimation to a face budget — [comfy.org/pixal3d-trellis2](https://comfy.org/pixal3d-trellis2/); "complex topologies, sharp features, and full PBR materials" — [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2/blob/main/README.md); official-code measurements: 484,921 faces with a 2048 px texture at 1024, 989,424 faces with 4096 px at 1536, reducible to ~100k faces — [maksonlee.com](https://www.maksonlee.com/install-trellis-2-wsl-2-ubuntu-26-04-rtx-5060-ti-16gb/)
- VERIFIED-PAGE. Input advice for the workflow: "a single, centered object with minimal occlusion and good edge contrast." — [runcomfy.com](https://www.runcomfy.com/comfyui-workflows/pixal3d-and-trellis2-comfyui-pbr-image-to-3d-glb). Multi-view in ComfyUI exists for Pixal3D only (turnaround sheet, `pixal3d_multiview_*` weights) — [docs.comfy.org/tutorials/3d/pixal3d](https://docs.comfy.org/tutorials/3d/pixal3d); feature requests for multi-view on TRELLIS.2 are open — [Comfy-Org/TRELLIS.2 discussions](https://huggingface.co/Comfy-Org/TRELLIS.2/discussions)
- VERIFIED-PAGE / VERIFIED-RAW. SAM 3D Objects: "designed to be robust in challenging natural images, handling small objects and occlusions, unusual poses"; outputs a Gaussian splat (`.ply`) and optionally a mesh GLB with vertex colours (demo default) or a 1024 px baked colour texture — [sam-3d-objects](https://github.com/facebookresearch/sam-3d-objects), [notebook/inference.py](https://github.com/facebookresearch/sam-3d-objects/blob/main/notebook/inference.py); a closed issue is titled "Baked Texture on Mesh (.glb) is extremely washed-out/pale compared to Gaussian Splat (.ply)" — [issue list](https://github.com/facebookresearch/sam-3d-objects/issues?q=is%3Aissue+VRAM+OR+memory+OR+Windows+OR+16GB+OR+12GB+OR+24GB)
- VERIFIED-RAW. TRELLIS v1: outputs "Radiance Fields, 3D Gaussians, and meshes"; multi-image is "tuning-free" and "may not give the best results for all input images." — [TRELLIS README](https://github.com/microsoft/TRELLIS/blob/main/README.md)

### Inferences
- For furniture cropped from listing photos (often partly hidden), SAM 3D Objects fits the input best and TRELLIS.2 the output best; a TRELLIS.2 crop of an occluded object will have invented or missing hidden sides unless the crop is completed first.

### Gaps
- No side-by-side evidence on occluded furniture crops.
